## 1. 先搞清楚两个概念

### 本地执行

任务跑在**Yomori 自己所在的这个 Windows 账户**里 —— 用的是本机 `ScriptRunner`，
和以前一样，不需要任何 RDP 环境。任务列表里没选通道的任务就走这条路。

### 会话通道

一条**会话通道**代表"另一套执行环境"：

```text
会话通道 = 目标主机 + 目标账户 + 该账户的凭据 + 一条专用的指令桥目录 + 一个画面连接
```

任务下发给通道后，会在**目标账户**里被一个常驻的「会话代理」执行，
进度和事件实时回传到 Yomori 这边，画面也直接内嵌在 Yomori 窗口里。

### 并行规则（一句话）

> **通道之间并行，通道内部串行。**

- 三条通道可以同时跑各自的任务队列；
- 同一条通道里的任务，仍按「任务执行」页的排序一条条跑；
- 本地执行的那一组，也是单独一条线，和通道任务同时进行。

一次执行最多并行 **8 条通道**，超出的会被截断（并明确告诉你哪几条没跑）。

## 2. 五分钟快速上手

假设你要把「另一个本机账户」跑起来：

> **前置检查：目标机器是否允许同时存在多个交互式会话。**
> 不允许时，第二条通道会顶替第一条的桌面，后续配置无法生效。
> Windows 客户端版默认仅允许一个交互式会话 —— **不用再手动装组件**，
> 设置页「远程桌面解锁（RDP）」可以自动解除这一限制；一次没有成功可以多试几次。
> **目标为另一台机器时无需此项配置** —— 各机器使用各自的会话。

| 步骤 | 在哪里 | 做什么 |
|---|---|---|
| 1 | 左侧「会话通道」→「通道管理…」 | 点「新建通道」（通道功能恒为开启，没有总开关） |
| 2 | 同上，通道列表 | 点「新建通道」 |
| 3 | 通道编辑卡 | 填通道名称、目标主机 `127.0.0.1`、目标账户 |
| 4 | 通道编辑卡 | 在密码框里填该账户的密码 → 点「保存凭据」 |
| 5 | 预检区 | 点「部署会话代理」（**仅绿色包需要**；安装版安装时已自动部署） |
| 6 | 预检区 | 点「重新预检」，确认没有阻塞项 |
| 7 | 左侧「任务执行」 | 左边选刚建的通道 → 中间「添加」任务（或把已有任务「移到通道…」过来） |
| 8 | 顶栏 | 点「开始执行」 |

> 远程桌面要在**目标机器**上开启（设置 → 系统 → 远程桌面），本应用不再提供一键开启。
> 目标是本机时，通道预检仍会检查这一项并在未开启时给出提示。

通道配好之后就会出现在左侧菜单「会话通道」**下面**（子菜单），点进去就是它自己的画面 ——
不用等开始执行。点父项「会话通道」本身则是**多画面**（全部通道并排）。

> 目标账户**至少要登录过一次**（切换过去登录一下再回来），代理才会被启动项拉起来。
> 只有代理被拉起并开始写心跳，预检里才会显示「在线」。

## 3. 界面地图

### 左侧菜单

```text
首页                    顶部一张随机横幅图 + 四个功能入口卡
任务执行                三栏：执行通道 / 该通道的任务 / 任务详情（按通道编排任务）
耗时统计                按来源（本机 / 各会话通道）汇总脚本耗时，用「来源」列区分是谁跑的
运行日志
会话通道 ▾              ← 父项：点它只展开/收起子菜单，本身不打开页面
  ├─ 多画面（全部通道）    ← 多画面页（全部通道 2×2 网格），入口就这一个
  ├─ 1 号机 · Player2    ← 点进去是该通道自己的画面页（可全屏 / 可弹独立窗口）
  ├─ 2 号机 · Guest
  └─ 通道管理…            ← 配置通道 / 凭据 / 部署代理 / 预检（配置都在这里）
设置                    版本号、检查更新（正式版 / 测试版渠道）、开发者模式、主题、关机与自启等本机设置
  ├─ 关于               版本号 + 更新渠道 + 「检查更新」+ 开源许可（第三方组件与许可证）
  ├─ 开发者             开发者模式开关（控制「运行日志」页显不显示 [embed] 诊断日志）
  └─ （其余卡片）        任务完成后关机/退出、外观、配置导入导出、目录入口
```

- 子菜单里列的是**配置里启用中的通道**（外加本轮在跑的通道），改通道配置后菜单即时跟着变；
- 通道项后面的状态、目标主机 / 账户，鼠标停上去的提示里有。

### 首页

顶部是一张大图，下面四张卡片分别进入任务执行、耗时统计、运行日志、通道管理。
执行状态不在这里显示，看右侧状态栏；通道入口在左侧菜单。

横幅图**不再是一张固定默认图**，而是从程序目录的 `assets/home_banners/` 图库里随机抽取：
每次启动、以及每次从别的页面切回首页，都会重新抽一张（图库里还有别的图时不会连着抽到同一张）。
往那个文件夹里加/删图片即可，不需要改配置。

| 操作 | 效果 |
|---|---|
| 在图上点右键 →「换一张」 | 立刻从图库里再抽一张（正在随机展示时才可用） |
| 在图上点右键 →「更换图片…」 | 选择 png / jpg / bmp / gif / webp 钉死为这一张，路径写入 config.json 的 `home_banner` |
| 在图上点右键 →「恢复随机展示」 | 清空 `home_banner`，回到图库随机（钉死过图片时才可用） |

- 图库只认 png / jpg / jpeg / bmp / gif / webp，同级的 `icon.ico`、`logo.png` 不会被抽到；
- 钉死的图只记录路径、不复制文件：原图被移动或删除后，首页回退到图库随机；
- 显示前按上限解码（宽 2048 物理像素、文件 32 MB 以内），避免超大原图占用大量内存。

### 多画面页（子项「多画面（全部通道）」）

| 区块 | 内容 |
|---|---|
| 头部 | 「连接全部通道」（给还没画面的通道各建一条内嵌连接）、「通道管理…」 |
| 画面区 | 2×2 网格，每格 = 一条通道的画面 + 通道名 + 状态 + 「全屏(无) / 弹出窗口 / 断开」 |

- 每页 4 格，通道多于 4 条时底部出现「上一页 / 下一页」；
- 没连接的格子会写「连接到这条通道」，点一下就连（不跑任务也能先看画面）；
- 每格右上角可「弹出窗口」，把它变成一个普通独立窗口；
- 多画面页不提供全屏，要放大某一路请点它自己的通道页。

### 通道管理页（子项「通道管理…」）

从上到下四块：

| 区块 | 内容 |
|---|---|
| 多会话说明 | 多条通道能否同时跑的判断依据（同一台客户端版机器只允许一个交互式会话） |
| 通道列表 | 全部通道；右侧「新建通道 / 复制 / 删除 / 重新预检」 |
| 通道设置（编辑卡） | 选中那条通道的全部字段 + 保存 / 清除凭据 |
| 通道预检 | 该通道的环境检查结果、代理状态、部署与移除代理按钮 |

### 通道画面页（子菜单里那条通道）

| 区块 | 内容 |
|---|---|
| 通道头 | 通道名、目标（主机 · 账户）、桥目录 + 「连接本通道 / 打开桥目录」 |
| 进度条 | 该通道自己的当前任务、n/N、已耗时、状态与心跳 |
| 画面区 | 本通道一格（占满） |
| 通道事件 | 该通道自己的事件列表（可「收起」把画面让大一点） |

### 设置页（版本号、检查更新与开发者模式）

| 位置 | 内容 |
|---|---|
| 「关于」卡片 | 版本号 + 运行环境；下面是**更新渠道**下拉框、「检查更新」按钮与结果提示 |
| 「关于」其余部分 | 作者链接、GitHub、赞赏入口、**「开源许可」入口** |

- **开源许可**列出随程序分发的第三方组件（FreeRDP、WinPR、OpenSSL、zlib、cJSON 等）及各自许可证；
  点「查看完整许可证原文」会用默认程序打开程序目录下的 `THIRD-PARTY-NOTICES.txt`，
  其中附有各组件的许可证与版权声明全文。
| 「开发者」卡片 | **开发者模式**开关（默认关），说明它也在这张卡片里 |
| 「远程桌面解锁（RDP）」卡片 | **「解锁 RDP」**一键解除 Windows 客户端「仅允许一个交互式会话」的限制（自动装多用户支持组件并改配置，不再需要手动照第三方教程操作）；另有「还原注册表」「卸载」两个回退入口。**一次没有成功可以多试几次**；反复失败时点「打开排查教程」按第三方手动方案处置，装完回来点「重新检测」 |
| 「UU 远程修复」开关（实验性） | 修 UU 远程连到被控通道会话的问题：打开后 UU 会连到本程序所在桌面，连接或开始执行后自动应用（应用时 UU 投屏进程会重启一次，远控短暂中断） |

- 版本号取自程序集版本（CI 发布时用的就是它），**不是写死的字面量**；
  本机自己 `dotnet build` 出来的包会显示成 `2.0.0-dev.local` 并额外标出提交哈希；
- **更新渠道**两档，选择会记进 `config.json` 的 `update_channel`：

| 渠道 | 比对的是 | 适合谁 |
|---|---|---|
| **正式版**（默认） | 手动发布的 `vX.Y.Z` | 只想用稳定版的人 |
| **测试版** | 每次提交自动构建的滚动版（含预发布） | 想抢先试新功能的人 |

- 「检查更新」只**读一次 GitHub 发布信息**：不下载、不安装、不改任何文件；
  有新版时点结果里的「前往下载」会用浏览器打开下载页，装不装由你自己决定；
- 结果提示四种：已是最新 / 有新版本 / 该渠道暂无发布（正式版还没发过时就是这个）/ 检查更新失败
  （网络、GitHub 限流都会说清原因，不会把查不到说成"已是最新"）；
- 所有检查结果与失败原因都会写进运行日志，排障时直接搜「更新检查」。

#### 开发者模式（「设置 → 开发者」）

| 状态 | 「运行日志」页 | 日志文件（`logs/`） |
|---|---|---|
| **关**（默认） | **不显示**带 `[embed]` 标签的内嵌画面诊断行 | 完整保留 |
| **开** | 显示这些行（D3D 初始化 / 渲染路径 / GFX 管线状态 / 帧到达节奏等） | 完整保留 |

- 那些诊断行是挂着内嵌画面时每 5 秒写一条的，几路画面并行跑起来会把「任务跑到哪一步、
  哪条通道出事了」这类要看的信息顶出屏幕，所以默认不上页面；
- 拨动开关**当场生效**：打开时这段时间攒下的诊断行会立刻补回页面，关闭时它们从页面上收走
  （页面上会留一行提示告诉你它们被收起来了、去哪儿打开）；
- ⚠️ 这个开关**只管页面显示，不管落盘**：日志文件在两种状态下都一模一样，
  所以别人发你一份日志让你看问题时，不需要让他先去开这个开关。

### 关闭按钮：收进状态栏还是退出

点窗口右上角的关闭（或 `Alt+F4`）**不会直接结束程序**，默认会先问一句。

| 按钮 | 效果 |
|---|---|
| **最小化到状态栏** | 窗口消失，托盘里留一个 Yomori 图标；任务、会话、内嵌画面全部照旧，进程继续跑 |
| **退出** | 结束程序。本地执行的任务会随之终止；**远程通道的任务在被控机上继续跑** |
| **取消** | 什么都不做（`Esc` 与右上角叉等同于取消） |

- 状态栏图标：**双击**或**左键单击**回到主界面；**右键**有「显示主界面 / 开始执行（执行中显示为停止执行）/ 关闭行为设置… / 退出」；
- 收进状态栏的第一次会弹一条通知提醒（只提醒一次），此后静默；
- 关闭弹窗里有两个**互斥**的勾选框（勾一个会自动取消另一个）：

| 勾选项 | 含义 | 记成什么 |
|---|---|---|
| 记住我的选择 | 这次点的按钮以后都照做，不再问 | `tray` 或 `exit` |
| 任务执行时隐藏到状态栏，空闲时退出 | 别按点的按钮，按当前状态决定：跑着就藏、没跑就退 | `auto` |

- 两个都不勾 → 这次选择生效，下次照样问；勾了「记住」却点「取消」→ 不记；
- 勾了「任务执行时隐藏，空闲时退出」时，**主按钮文案会跟着状态变**：
  正在跑任务时写「隐藏到状态栏」，空闲时写「退出」—— 按钮上写的一定是按下后真会发生的事；
- 想改回来：**设置页 → 外观 → 关闭按钮**，四档（每次询问 / 最小化到状态栏 / 直接退出 / 任务执行时隐藏，空闲时退出），
  托盘右键菜单里的「关闭行为设置…」也能直接跳过去；
- 「收进状态栏」不等于任务隔离：它还是同一个进程，只是窗口不可见。
  多用户 RDP 切换导致当前会话锁定期间，托盘图标也不可见（锁回来就有）；
- 程序是**单实例**的：已经收进状态栏后再双击一次 exe，不会起第二份，只会把已有窗口叫回前台。

## 4. 配置一条会话通道

在「会话通道」→「通道管理…」页选中一条通道，编辑卡里逐项填。

### 字段说明

| 字段 | 说明 |
|---|---|
| **通道名称** | 左侧菜单与各处的显示名。留空会按账户名自动起一个 |
| **目标主机** | 本机另一个账户填 `127.0.0.1`；另一台机器填 IP / 主机名，可带端口如 `192.168.1.20:3390`；填 `rdp://xxx` 会自动去掉前缀 |
| **目标账户** | 该机器上的账户名。**一条通道一个账户，别让两条通道共用一个账户**（它们抢同一个会话） |
| **指令桥目录** | 本机多账户**留空**（自动按账户名分目录）；目标是别的机器时填双方都能读写的共享路径 |
| **密码框** | 只用于点「保存凭据」，存进 Windows 凭据管理器，**不写进 config.json** |
| **远程桌面窗口尺寸** | 「自动」= 内嵌跟随画面格子大小；选固定档位则按该尺寸连接 |
| **该通道任务全部结束后的会话处理** | `保持 / 断开 / 注销`，按通道各配各的 |
| **启用该通道** | 关掉后该通道的任务不会下发（本轮跳过并给出原因） |

### 保存时机

- **文本框**（名称 / 主机 / 账户 / 桥目录）：**焦点离开输入框就自动落盘**，不会因为切页丢填；
- **下拉 / 开关**（分辨率 / 收尾方式 / 启用）：改动即落盘；
- 「保存通道设置」按钮：兜底确认用，不点也不会丢。

### 凭据

- 密码框里填好密码 → 点「保存凭据」。同一台主机上的**不同账户各存一条**，互不覆盖。
- 「清除已保存凭据」按钮按「主机 + 账户」删除，不影响同主机的其它账户。
- 如果系统组策略禁止读写凭据管理器，日志会提示"写入后无法读回"，此时只能手动输入密码。

### 账户权限（保存凭据之后会发生什么）

保存本机通道的凭据后，程序会顺带检查该账户是不是本机管理员：

| 情况 | 结果 |
|---|---|
| 已是管理员 | 只提示「账户已是本机管理员，无需修改」，不写入、不记账 |
| 不是管理员 | 先弹一次确认框；确认后把该账户加入 Administrators（授予本机管理员权限） |
| 取消确认 | 只取消授权，**已经保存的凭据仍然保留** |
| 远程主机 | 不弹框、不动本机账户；提示需在目标计算机上设置管理员账户 |

几条固定边界：

- **只追加，不搬迁**：Users、Remote Desktop Users 等原有组成员关系全部保留，程序不会把账户
  从某个组里移出来。
- **不再按系统版本分流**：家庭版、专业版、企业版走同一套规则，也不再依赖「远程桌面用户组」是否存在。
- **需要重新登录才生效**：管理员身份由新登录令牌体现。程序不会强制注销、不强制断开连接、
  不重启远程桌面服务；已有会话仍在用旧令牌，等该账户下次登录后才完整生效。
- **本版本不提供自动降权**：没有「取消管理员」按钮，也不会因为删除通道、清除密码、卸载而自动降权。

确认框出现时，授权结果会显示在通道编辑卡里的「管理员授权」一行，与「凭据：已保存」分开报告。

### 收尾方式怎么选

| 选项 | 效果 | 什么时候用 |
|---|---|---|
| 保持 | 会话放着不管，下次还能直接复用 | 一整天要跑好几轮 |
| 断开 | 断开画面连接，进程与会话保留 | 想省一点资源，但不想重新登录 |
| 注销 | 会话销毁，里面的代理与脚本一起结束 | 跑完就收工；**注意会连带杀掉正在跑的东西** |

## 5. 部署会话代理

跨会话启动进程，Windows 上只有"从那边动手"这一条路，所以代理是**随目标账户登录自启、然后常驻**的。

### 安装版会自动部署

用安装包安装时，这一步在安装过程中就做完了：安装程序铺完文件后会调用
`Yomori.exe --deploy-agent`，把代理副本与登录自启项一并准备好。**装完即可直接连接**，
不需要再点一次「部署会话代理」。

- **覆盖安装**会顺手把副本更新到新版本；已有的自启项保持原参数不动（其中的桥目录是你在
  通道配置里定的，安装程序不替你改）。
- 若安装目标机上某个账户的代理**正在执行任务**，自动部署会整轮跳过（不打断任务）。
  安装结束后在「通道管理」里手动点一次「部署会话代理」即可补上。
- 部署结论写在安装目录的 `logs\agent_deploy.log`，出问题先看它。
- **绿色包（解压即用）没有安装过程**，仍需手动部署一次。

### 部署做了什么

```text
1. 把代理复制到公共目录（所有用户都读得到）
   目标：C:\ProgramData\Yomori\agent\
2. 在公共启动目录建快捷方式
   C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup\Yomori RDP 会话代理.lnk
   → 目标：C:\ProgramData\Yomori\agent\Yomori.Agent.exe --rdp-agent
3. 目标账户下次登录时，快捷方式拉起代理；代理常驻等待指令
```

**为什么必须复制一份**：主控端程序在自己的用户目录下（`C:\Users\<你的账户>\...`），
这个路径**不给其他账户读权限**，快捷方式会被静默拒绝 —— 表现为"远程桌面连上了，任务就是不执行"。
复制到 `%ProgramData%` 就绕开了这个问题。

### 三个要点

1. **只需部署一次**：安装版在安装过程中已自动部署，覆盖安装也会自动更新副本；
   绿色包升级后需要手动点一次（见第 11 节）。
2. **远程目标要在对方机器上部署**：本机的「部署会话代理」按钮管不到另一台机器。
3. **部署后要注销目标账户再重连**：代理是登录时被拉起的，已在登录状态的会话里不会自动多出一个代理。

### 副本被占用时

代理是常驻进程，会一直持有副本目录里的 DLL，此时覆盖部署会被系统拦住。程序会按三档处理：

| 档 | 情况 | 做法 |
|---|---|---|
| ① | 副本目录没被占用 | 原地覆盖，最干净 |
| ② | 被占用，但旧代理**空闲** | 先送走空闲的旧代理，再原覆盖 |
| ③ | 旧代理**正在跑任务** / 送不走 | 跑任务时**拒绝部署**；送不走则退到备用目录 `agent_b` 并改快捷方式 |

> 如果部署失败并提示"需要管理员权限"，多数时候那是**误报** ——
> 真正的原因通常是文件被占用。日志里会写清楚到底是权限问题还是占用问题。

## 6. 按通道编排任务

「任务执行」页是**三栏**：

| 栏 | 内容 | 你能做什么 |
|---|---|---|
| 左：执行通道 | 「本地执行（当前会话）」+ 各条通道（+ 末尾的「未知通道」） | 点一条，中间就切到它的任务 |
| 中：这条通道的任务 | 序号 = 通道内的执行顺序 | 添加 / 删除 / 上移 / 下移 |
| 右：任务详情 | 顶部「所属：<通道名>」 | 编辑任务；「移到通道…」改派 |

- **「本地执行」永远在第一项**，也是新建任务的默认归属 —— 避免"忘了选通道，任务悄悄跑远程"；
- 上移 / 下移**只在当前通道内**生效，别的通道顺序不会被动；
- 「移到通道…」会把任务放到目标通道**末尾**，并自动切到那条通道（不然任务像凭空消失了）；
- 通道列表的顺序 = 「通道管理…」页里的顺序，也决定了并发名额的先后。

### 停用的通道里能排任务吗

能。停用 / 没配账户的通道会置灰并写明原因，但**照样能往里排任务** ——
它们只是本轮不执行，方便你先排好再启用。

### 删除通道时里面的任务怎么办

删通道时会先弹框问「这些任务交给谁」，默认**移回本地执行**：
也可以选别的通道，或选「保持未知」（那些任务本轮不执行）。
所以正常操作下不该再出现「未知通道」。

### 引用了不存在的通道会怎样

如果某个任务的 `channel_id` 指向一个**已被删除 / 已停用 / 没配账户**的通道，
这条任务在该轮**不会执行**，并在日志里写明原因。
它**不会**偷偷改成本地执行 —— 因为那可能把已经在目标机跑着的游戏重复拉起来。

### 启动命令 / 参数：选完脚本就能选参数

选好「脚本路径」后，这一格是**可下拉、也可直接写**的：

- **下拉**里是这个脚本已知的启动参数（如三月七的 `daily -e`、BetterGI 的 `startOneDragon`、
  MaaPiCli 的 `-d`），每项带一句作用说明；参数为空时自动预填一条最常用的。
- **直接打字**就是自定义参数。程序不会拦你 —— 上游随时可能加新参数；写完会做一次校验：
  认识的参数显示它的作用与前置条件，不认识的给黄字提醒，并列出最接近的已知参数。
- 下面一行灰字是**完整命令行**，可以选中复制到终端里先试跑一次。
- 勾着「**同时套用推荐设置**」时，选中参数会顺带写好完成判断（进程 / 窗口 / 直接等待，只写一种）、
  最大运行时间与外部日志目录；关掉它就只写参数。

识别的依据是**可执行文件名**和目录里的 `interface.json`：
后者含 Mirror酱的项目 id，所以同一个 `MFAAvalonia.exe` 在不同项目目录里能被区分开。
认不出来的脚本也不会出错，照样手填即可。

> 带实例名 / 配置名的参数（`--autostart -i 实例名`）不下拉，说明行会给出写法，照着改一下即可。

## 7. 执行、监控与停止

### 开始

点顶栏「**开始执行**」。日志会先写一行「本轮启动 N 条会话通道并行执行」，然后：

1. 本地那组直接开始跑；
2. 每条通道依次：连接目标账户 → 等待代理在线 → 下发 `command.json` → 轮询进度；
3. 还没连接的通道会自动连接（内嵌模式不会弹任何窗口）。

### 监控三个地方

| 位置 | 看什么 |
|---|---|
| 左侧「会话通道」→ 子菜单里某条通道 | 画面 + 该通道进度、心跳、事件 |
| 主页「会话通道」概览卡 | 一眼看完各通道状态（1Hz 刷新） |
| 主页状态卡 | 整轮口径：单通道时就是那条通道；多通道时是「执行中（N 块并行）」、进度求和、耗时取整轮墙钟 |

### 心跳与失联

代理等待指令期间每秒写一次心跳。主控端的判定顺序是：

1. **先看这条状态是不是本轮指令写的** —— 不是就当作"代理还没接到指令"，**不报失联**；
2. 刚下发指令的 30～90 秒是宽限期（登录 + 拉起代理 + 初始化大约要 25 秒），期间不报失联；
3. 过了宽限期才按"多久没更新"判断，并区分是否处于活动状态。

一条通道失联**只影响那一条**，其它通道照常。心跳恢复后会补一条「✓ 会话代理心跳已恢复」的日志。

> 折中：90 秒以内的真断线，最迟要等到宽限期结束（约 90 秒）才会告警。

### 停止

| 操作 | 快捷键 | 行为 |
|---|---|---|
| 停止执行 | `F8` | 队伍立即停（不会"跑完当前任务"），并按**全部任务配置**做统一收尾；同时给**每条通道**各写一份 `stop.json` |

> 早期版本有「停止」和「紧急停止」两个档位，区别只在清理范围（当前轮 / 全部任务配置）。
> 现在合并成一个按钮：既然只留一个入口，它就必须能停干净，所以统一按全部任务配置收尾 ——
> 连「启动后不等待」那类已经脱离本轮的进程也会扫到。旧版主控端下发的
> `stop.json`（`emergency = true`）仍然兼容，效果与「停止」相同。

代理有**一条独立的 500ms 循环**盯着 `stop.json`（与任务执行并行，任何阶段都能响应），
读到就转成脚本引擎的停止请求、把相位切成 `stopping` 作为回执，随后按
「启动脚本进程 → 目标进程 → 游戏窗口/扩展进程」三层顺序收尾。

主控端这边不是"发一次就不管"：

- 按下停止后日志会先出现 `已向 N 个通道发送停止请求`；
- 代理回执到了会补一条 `目标会话的代理已收到停止请求，正在收尾。`，
  同时状态文案固定成「已请求停止，目标会话正在收尾…」；
- 5 秒没回执就**自动补发**（最多 5 次）。超过上限还没回执，日志会直接点名
  「目标会话的代理多次未响应停止请求，很可能还是旧版本」—— 这时重新「部署会话代理」即可。

所以按下停止后**有一拍延迟**（半秒左右）是正常的；但收尾本身要杀进程、关游戏，
慢一点也属正常，看日志里的回执行就能区分"在收尾"和"压根没收到"。

不管停止请求到达时任务处在哪个阶段（刚拉起、正在确认启动、正在等游戏窗口消失、并发组里），
三层清理都会执行到；提权 / 单实例接力起来的新进程也在清理范围内。

清理时日志会**逐条写明结果**，不再只写"正在结束"（以 March7th + 崩铁为例）：

```text
停止执行：正在清理本轮监控到的实际进程：StarRail
停止执行：结束进程名「StarRail」：已结束                       ← 每一条都带回执
停止执行：任务「…」正在清理启动脚本进程：March7th Launcher.exe
停止执行：结束进程名「March7th Launcher.exe」：已结束
停止执行：任务「…」正在清理目标进程：星穹铁道, 星穹铁道.exe
结束进程名「星穹铁道」：未能结束：错误: 没有找到进程 "星穹铁道"。
按目标进程关键词兜底结束：星穹铁道 -> PID 54012 (StarRail)
  ↳ 窗口「星穹铁道」：已结束
停止执行：✓ 已复查确认，任务相关的进程都已结束。               ← 结论行，看这一行就够
```

**看最后一行结论即可**：

- `✓ 已复查确认，任务相关的进程都已结束` → 进程真的没了。
  若此时内嵌画面还停在游戏上，那只是**画面没刷新**（点「断开」再「连接本通道」即可），
  不是游戏还在跑。
- `⚠ 复查发现 N 项仍在运行：…` → 没杀掉。往上找 `未能结束：…` 的原因，
  多半是游戏带反作弊 / 驱动级保护。可以：① 让目标会话以**管理员**身份运行代理；
  ② 在目标会话里手动结束。

另外，程序会在启动后记下游戏的真实镜像名：

```text
已记下监控命中的真实进程名：StarRail（PID 54012）—— 停止时按它清理与复查，不再依赖窗口标题。
```

因为配置里写的「星穹铁道」「原神」是**窗口标题**，而真实进程名是英文
（崩铁 = `StarRail`、原神 = `YuanShen`）—— 按中文名杀是打不中的，只能靠窗口标题兜底。
**最稳的做法：把这类英文镜像名也补进任务的「进程关键词」**，这样不依赖窗口是否存在，
复查也能覆盖到它。

### 收尾

- 每条通道按它自己配的「会话处理」方式收尾（保持 / 断开 / 注销）；
- 整轮全部结束后，日志出现一行 `[汇总] 共 N 块（本地 X / 通道 Y）：成功 …、异常 …。`，
  下面跟逐块明细（**异常块排在最前面**）；
- 通知**只从主控端发**（目标会话里弹的你看不到，代理侧已不再发）：每条通道整条跑完 / 失联时弹一条
  「Yomori：通道「x」任务结束」（`rdp.notify_on_channel_done`），整轮结束时再弹**一条**汇总
  （`rdp.notify_on_all_done`）。单块执行（只有本地，或只有一条通道）不发汇总 —— 它和按块通知重复；

## 8. 画面：多画面 / 单通道 / 全屏

画面在**两个地方**看，位置和"同时看几路"有关（跟连接模式是两回事）：

| 想看的 | 去左侧菜单 | 说明 |
|---|---|---|
| 全部通道并排 | 点「会话通道」父项（或子项「多画面（全部通道）」） | 2×2 网格，每页 4 格 |
| 某一条通道放大 | 点子菜单里那条通道 | 本通道一格占满，**有全屏** |

### 多画面（父项「会话通道」）

网格并列显示全部通道（配置里启用中的 + 本轮在跑的），每格标通道名与状态：

- 通道多于 4 条时出现「上一页 / 下一页」（**翻页**，不是滚动）；
- 没连接的格子写着「连接到这条通道」，点一下就连；头部还有「连接全部通道」一键连；
- 每格可单独「弹出窗口」→ 变成一个普通可缩放窗口，你可以自己并排摆放；
- 关掉弹出窗口后，画面**自动回到**页面里那一格；
- **多画面不提供全屏**（会盖掉其它几路），要放大某一路请点它自己的通道页。

为什么每页 4 格：8 路画面同时渲染的 CPU / GPU 开销不可接受。分页天然保证"同时渲染不超过 4 路"，
翻页时用不到的格位会被解挂、不参与渲染。

### 单通道页（子菜单里那条通道）

只摆本通道一格，占满整个画面区。**保留「全屏」**（画面右上角）：

- 全屏会开一个独立的全屏窗口，并接管键盘 —— `Win`、`Alt+Tab` 等系统组合键会**转投远端**；
- `F11` 退出全屏，退出后本地键盘立即恢复；画面上的双击不参与全屏切换；
- 同时只允许一个全屏窗口：从另一条通道再点全屏，前一个会被自动收掉。

### 操作画面

点击画面获得焦点后，鼠标与键盘直接作用于远端。

| 情况 | 说明 |
|---|---|
| `Ctrl+Alt+Del` | 系统安全序列，**任何客户端都转发不了**；远端任务管理器请用 `Ctrl+Shift+Esc` |
| 画面黑屏 | 程序会自动重试几次；仍黑屏就点「断开」再重连，或把连接方式改回「独立窗口」 |
| 几路画面互相闪烁 | 一个客户端同时只能挂一块画面。先关掉那路的弹出窗口再重开 |
| 画面太小 | 点事件卡的「收起」，画面会多拿一块高度；窗口拉大也有用 |

### 独立窗口模式（`mstsc`）

在通道管理页把「连接方式」改成「独立窗口」，之后连接会用系统自带的远程桌面客户端开窗口。
这是最稳、永远可用的兜底方案，但画面不在 Yomori 里，也**不支持多画面同屏**。

## 9. 几种典型配置

### A. 一台机器 + 两个账户

```text
通道 1：主机 127.0.0.1 / 账户 Player2    桥目录留空
通道 2：主机 127.0.0.1 / 账户 GameBot    桥目录留空
```

能否真正同时跑，取决于你的系统是否允许多个交互式会话并存。
如果不能，第二个连接会把第一个桌面顶掉 —— 这种情况请用方案 B，或在设置页点
**「解锁 RDP」**自动解除限制（应用内一键完成；一次没有成功可以多试几次）。

### B. 两台机器

```text
通道 1：主机 192.168.1.20 / 账户 Player2   桥目录 \\192.168.1.20\YomoriBridge
通道 2：主机 192.168.1.21 / 账户 Player2   桥目录 \\192.168.1.21\YomoriBridge
```

要点：

- 桥目录两边都要能读写（共享文件夹 / NAS / 同步盘都行）；
- 代理要在**对方机器**上各自部署一次；
- 对方机器上也要装一份 Yomori（部署按钮就是从当前程序复制的）。

### C. 混合：本地 + 远程

```text
任务 A → 本地执行（当前会话）
任务 B → 通道 1
任务 C → 通道 1
任务 D → 通道 2
```

执行结果：本地一条线、通道 1 一条线（B 跑完才跑 C）、通道 2 一条线，三条线并行。

## 10. 配置文件长什么样

配置在仓库根的 `config.json`（与 Python 版共用同一份）。会话通道相关的部分：

```jsonc
{
  "update_channel": "stable",   // 检查更新看的渠道：stable = 正式版；beta = 测试版
  "developer_mode": false,      // 运行日志页要不要显示带 [embed] 标签的内嵌画面诊断行
  "rdp": {
    "enabled": true,
    "client_mode": "embedded",        // embedded = 内嵌画面；mstsc = 独立窗口
    "audio_enabled": true,
    "gfx_enabled": false,
    "connect_timeout_seconds": 120,
    "notify_on_task_done": true,      // 每个任务完成在主控端发一条通知
    "notify_on_channel_done": true,   // 每条通道整条跑完 / 失联时发一条
    "notify_on_all_done": true,       // 整轮结束发一条汇总（多块才发）

    "channels": [
      {
        "id": "ch-7f3a",              // 稳定 id，任务的 channel_id 指向它
        "name": "1 号机 · Player2",    // 菜单显示名
        "host": "127.0.0.1",
        "user": "Player2",
        "bridge_path": "",            // 留空 = <ProgramData>\Yomori\rdp\<user>
        "credential_saved": true,
        "session_finish": "keep",     // keep / disconnect / logoff
        "desktop_width": 1280,
        "desktop_height": 720,
        "enabled": true
      }
    ]
  },

  "tasks": [
    { "name": "原神", "channel_id": "ch-7f3a", "order": 1 },
    { "name": "星铁", "channel_id": "",        "order": 2 }   // 空 = 本地执行
  ]
}
```

**密码永远不在这个文件里** —— 它只存在 Windows 凭据管理器中，键为 `Yomori/RDP/<主机>|<账户>`。

### 命令行参数（排查用）

| 参数 | 用途 |
|---|---|
| `--rdp-agent` | 以会话代理身份启动（部署快捷方式时自动带上；一般不用手敲） |
| `--bridge:<目录>` | 指定桥目录（代理用，远程目标部署时由部署流程写入快捷方式） |
| `--embed-vm <host> <user> <password>` | 自检：走正式 VM 路径自动连接一条内嵌会话，过程全写日志 |

## 11. 升级注意

### 从旧版本升级必做

桥目录规则变了：

```text
旧：<ProgramData>\Yomori\rdp\
新：<ProgramData>\Yomori\rdp\<账户名>\
```

**必须让代理换成新版本**：安装版覆盖安装会自动更新副本（绿色包需手动点一次「部署会话代理」），
然后**注销目标账户再重连**。
否则新版主控端在新目录读写、旧代理还在旧目录里转，表现就是「代理明明在跑，却一直显示不在线」。

### 会自动完成的迁移

- 旧配置里没有 `channels` 时，会**自动迁移出一个默认通道**（继承原来的目标账户、桥目录、分辨率、收尾方式），
  并把所有任务指向它 —— 也就是说，升级后**原来能跑的行为不变**，不需要手工重配；
- 旧桥目录里的 `status.json` 如果还在旧位置，程序会给出提示。

### 行为变化

- 内嵌画面改用原生 FreeRDP 实现，旧 COM ActiveX 方案（`Yomori.RdpHost`）已删除；
- 旧的「远程会话」菜单项已改名为「会话通道」，原来的单通道配置界面（`RdpPage`）被拆成
  「会话通道（管理）」+「各通道画面页」两个部分；
- 左侧菜单的通道项改成**「会话通道」父项下的子菜单**：父项 = 多画面（全部通道网格），
  子项 = 各通道单独画面 + 「通道管理…」（原来的配置页挪到这里）。配置内容没变、`config.json` 不用动；
  通道不再等"开始执行"才出现 —— 配置里启用的通道一启动就在子菜单里；
- 远程执行时顶栏「停止执行」**现在真的可用**（改造前远程模式下它是灰的）。

## 12. 出问题先看这里

| 现象 | 先查什么 |
|---|---|
| 预检说代理未部署 | 点「部署会话代理」（需要管理员）。远程目标要在对方机器上部署 |
| 预检说代理不在线 | 目标账户**登录过**吗？登录过还不行就注销再重连一次（代理是登录时拉起的） |
| 「代理在跑却显示不在线」 | 是不是刚从旧版本升级上来？**重新部署一次代理**（桥目录规则变了） |
| 开始执行后提示"本轮未启动" | 看日志里逐条写的原因：超 8 条上限 / 通道被停用 / 没配账户 / `channel_id` 指向了已删除的通道 |
| 任务完全不执行 | 打开 `%ProgramData%\Yomori\rdp\<账户名>\status.json`：`AgentUser` 为空、时间停在"下发那一刻" = 目标会话里的代理没起来 → 重新部署代理 |
| 停止执行没反应 | 先看日志有没有 `目标会话的代理已收到停止请求`：有 = 链路通，只是目标进程收尾慢；没有就看日志有没有「已下发 N 次…始终没有回执」—— 那是**目标会话里还是旧版本代理**，重新「部署会话代理」后注销目标账户重连。再顺手看一眼该通道 `status.json` 的心跳时间，不走说明代理已不在 |
| 某条通道报失联，别的正常 | 那是**预期行为**：只有那一条通道受影响。先看它目标账户的桌面是否被注销了 |
| 提示需要填「指令桥目录」 | 目标是远程主机时的正常拦截；只想切本机账户的话把主机改回 `127.0.0.1` |
| 画面黑屏 | 点「断开」再重连；仍不行就把连接方式改成「独立窗口」 |
| 画面挤在一条横带里 | 点事件卡的「收起」，或把窗口拉大 |
| 全屏后本地键盘失灵 | 按 `F11` 退出全屏（退出时会先摘键盘钩子，本地立即恢复） |
| 分辨率不是我想要的 | 改档位后要**重新连接一次**；内嵌模式的分辨率跟随画面格子大小 |
| 运行日志里少了 `[embed]` 开头的 D3D / 帧率诊断行 | **预期行为**（默认不显示，免得淹掉任务进度）。去「设置 → 开发者」打开**开发者模式**即可看到。⚠️ 日志文件 `logs/` 里始终完整保留，跟这个开关无关 |
| 「检查更新」说该渠道暂无发布 | 正式版通道专有：**这就是「还没发过正式版」**。想看自动构建的版本，把更新渠道切到「测试版」 |
| 「检查更新」说请求太频繁 | GitHub 匿名接口每小时 60 次上限，等提示里的时间过了再点 |
| 「检查更新」说本机自编译版 | 你跑的是自己 `dotnet build` 出来的包（版本号带 `-dev.local`），本来就和发布版对不上号；要跟官方版本对齐就用「前往下载」换正式包 |
| 想彻底重置 | 删掉 `config.json` 里的 `rdp.channels` 节点（配置丢），或删掉整份 `config.json`（全部回默认） |
| UU 远程连到了通道账户的桌面 | 设置页打开**「UU 远程修复」**开关（实验性），连接或开始执行后自动应用；应用时 UU 投屏进程会重启一次，远控短暂中断属正常 |
| 一键解锁反复失败 | 先按提示**多试几次**；仍不行就点卡片里的「打开排查教程」，按第三方手动方案自己装，装完回来点「重新检测」确认状态 |

完整的排障表（含 RDP 层与凭据层的问题）见 [README.md 的「排障」一节](README.md#排障)。
