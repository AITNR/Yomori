# 外部脚本实时日志

通道页底部提供「运行事件 / 实时日志」。运行事件保留任务开始、完成、停止等信息；脚本输出进入独立实时日志窗口，默认保留最近 200 行。跟随底部可手动关闭，上翻滚轮或 PageUp/Home 时会暂停跟随。级别筛选和「清空当前显示」只影响界面，不删除源日志或归档。

## 配置

在「任务执行 → 任务详情 → 进阶设置 → 外部脚本实时日志」开启跟踪，填写目标账户能读取的日志文件或目录。相对路径相对于脚本目录解析，环境变量在实际执行账户下展开。使用目录时请缩小文件匹配范围，同目录的诊断/更新器日志未必是任务进度日志。

### 推荐值

选中脚本路径后，程序会按识别出的项目填好这一区的五项（目录 / 模式 / 编码 / 末尾跟随 / 关键字），并在顶部显示一行来源：

```
日志位置来自源码核实 · 三月七小助手：logs · 模式 20??-??-??.log
```

- 来源分四档：本机实测、源码核实、框架规则、推测。推测只出现在未收录项目的通用探测上。
- 推荐值挂在 `Presets/launch_presets.json`：6 套通用前端给默认值（如 MFAAvalonia → `logs` + `log-*.log`），
  少数项目覆盖（三月七只要 `logs`、MAA 用 `asst.log`），不在项目表里的工具按可执行文件名兜底
  （AUTO-MAS → `debug` + `app.log`）。
- **只填不改锁**：五个字段都可随手改。一旦与推荐值不同，状态行变「已自定义（推荐值：…）」并出现
  「还原推荐值」，此后换脚本或重新识别都不会覆盖你的值。
- 明确不落盘日志的项目（如 Better-HSR-Currency-Wars、ArkLights）不写路径、不打开开关，
  状态行直接说明原因与替代取证方式。
- 需要递归子目录的项目（LALC 的 `logs\<时间戳>\run.log`、ok-Onmyoji 多开时的 `logs\<实例id>\`）会自动勾上「包含子目录」；
  采集端有深度 3 层、500 个文件两道闸，超限会在日志窗口提示一次。

「文件匹配模式」支持用分号写多个（如 `maafw.log;maa.log`，覆盖两代内核的文件名）。
`\r` 视为行界：进度条用回车刷新同一行时只保留最后一段（`10%\r20%\r30%` 只出现 `30%`），
不会攒成一条超长行被丢弃，也不会把上千次刷新全灌进面板。

下面是本机样本的示例，安装位置和版本变化时须重新确认：

| 脚本 | 目录示例 | 建议匹配 |
|---|---|---|
| BetterGI | `C:\Program Files\BetterGI\log` | `better-genshin-impact*.log` |
| March7thAssistant | `C:\Program Files\March7thAssistant_v2.7.0\logs` | `20??-??-??.log`（避免跟到 `config_diag.log`） |
| MaaEnd | `D:\Program Files\MaaEnd\debug` | 先确认要看 `mxu-tauri.log`、`maafw.log` 或其他组件；优先指定文件 |

## 显示视图

同一份日志可以按三种视图看，切换只改变"看什么"，不改采集内容，也不重新解析：

| 视图 | 内容 | 适用 |
|---|---|---|
| **面板**（默认） | 任务开始 / 完成 / 失败、项目作者写的提示、60 秒心跳 | 日常盯着看：现在在做什么、做到哪一步、为什么停 |
| **节点** | 每个节点的进出、识别失败折叠、告警 | 排障：它到底点了哪些按钮 |
| **原文** | 未投影的原始行（仍只保留 INFO 及以上） | 报 issue、核对内核行为 |

MaaFramework 系（MFAAvalonia / MXU / MFW / MaaPiCli，40 余个项目）默认走面板视图。它把两类信息接起来：

- **任务名**取自项目资源：`interface.json` → `tasks/*.json` 的 `{entry, label}` → `locales/**/zh_cn.json` 的词条，
  所以显示的是「任务开始：🤝拜访好友」而不是 `VisitFriendsMain`。
- **过程提示**取自内核日志的 `details.focus`（项目作者自己写的那句话），
  例如「正在检查画面，提示登出账号是正常现象」「画面检查通过」。
  该字段只在"键等于当前事件"时显示，避免同一句跟着五个事件重复。
- **节点名**取自项目资源的 `resource/pipeline/*.json`：节点名本身是英文
  （`AncientTreeQuickTeleport`），中文在节点的 `desc` 里（「在古树任务地图中点击传送」），
  实测 MaaEnd 6,561 个节点里 5,776 个带 `desc`。面板显示 `desc`，节点档仍记原名。
  名字既无 `desc` 又无中文的（agent 动态注册的 `Stack.…` 之类）不上面板；
  但**节点失败一定会显示**，查不到中文就退回原名，同一节点 2 秒内去重。

归档写的是**节点档**：事后排障要的是"跑到哪一步断了"，面板那几行人话不够用。

两处降级：

- 项目没写 `focus`（MaaFW 4.x 的项目常见）时，退回显示节点名；节点名本身是中文的项目照样可读。
- 节点名 30 秒内只出一条，避免同一节点反复触发刷屏；任务长时间没有输出时补一条心跳，
  日志出现 5 分钟以上空档时补一条「日志中断」。

非 MaaFramework 的日志（三月七 / BetterGI / ok-script / 一条龙 / AUTO-MAS）不做投影，原样显示。

「从文件末尾开始跟踪」开启时，为脚本启动前已存在的文件建立末尾基线；本次新建或轮转的文件从头读取。关闭时可读取已有内容。编码支持自动、UTF-8 和 GBK；无法确认编码时可显式选择。仅转发完整行，半行等待后续换行；单行按既有规则规整和截断。外部程序自身缓冲未写入磁盘的内容无法采集。

升级主控后需重新部署会话代理，新协议的主控与代理需要同时更新。旧代理会在实时日志状态区显示不支持提示，普通任务事件仍可接收。目标账户无权限、路径错误等诊断出现在日志窗口中，不改变任务结果。

## 数据流与边界

- 每个任务独立后台跟踪；并发任务不会替换另一任务的采集器。
- 本地执行通过 UI 队列批量应用；远程执行按通道桥目录传输。
- 代理每约 250ms 批量追加 `live-log-<commandId>.ndjson`，每条记录占一行，包含批次、序号、时间、任务名、级别与正文。
- 主控约每秒按字节偏移读取，文件 I/O 位于后台线程；仅完整行进入解析，按批次和序号防重复。
- `status.json` 只承载进度和普通事件，不逐行重写脚本日志。代理在发布完成事件及会话收尾前刷新最后一批日志。
- 桥目录按最近 30 次运行保留实时日志传输文件；原有 `external_logs/<通道>/<日期>.log` 归档沿用设置页保留策略。
- 传输暂时失败会重试。实时重试队列有上限，积压超限有提示；需要完整内容时查看脚本自身日志。界面窗口与队列均有上限，不承诺所有日志永远留在内存。
- `启动后不等待` 的采集持续至本轮队列结束；本轮结束后仍在后台运行的程序不会继续回传。

## 验证

```powershell
dotnet run --project winui3/tests/Yomori.LogChecks/Yomori.LogChecks.csproj -c Release
dotnet build winui3/src/Yomori.App/Yomori.App.csproj -c Release -p:Platform=x64 -p:RuntimeIdentifier=win-x64
```

回归工程直接链接生产的采集器、桥协议与通道状态代码，覆盖完整/半行、中文、跨块编码、轮转、截断、增量去重、批次隔离、容量和普通完成事件。编译及合成脚本通过后，真实目标账户的权限、部署副本和三种脚本当前版本仍须通过现场运行验证；读取现有日志样本不等同于跨账户执行成功。
